# 实验 3：分叉实验（DivergenceProbe）

**问题**：同一个存档、没有任何玩家输入，两次运行（两个进程，相当于两台机器）从第几个 tick 开始不一样？先从哪里开始？增长多快？
这决定主机/服务端多久纠正一次、纠正哪些东西、要多少带宽（见 `architecture.md`）。

## 做法
- mod：`src/DivergenceProbe`，安装：`./build.sh DivergenceProbe`。
- 在主菜单自动读取 `config.json` 里的 `savePath`（目前是 c02，第 476 周期，16 个复制人，原版），读档后先暂停 `settleFrames` 帧，再按变体设置后以速度 1 运行 `ticksPerRun` 个真实 200 ms tick，然后自动重启游戏进行下一次运行。
- 变体（成对比较）：
  - `natural` ×2：不做任何干预。
  - `seeded` ×2：读档开始和取消暂停时 `UnityEngine.Random.InitState(seed)`。
  - `fixeddt` ×2：seeded + `Time.captureDeltaTime = 1/60`（每渲染帧恰好一个模拟子 tick，消除帧率影响和零步长模拟调用）。
- 每个 tick 记录（`ticks.bin`）：随机数状态哈希；元素/质量/温度/病菌四个字段各自的全图哈希；每个 32×32 区块的哈希；复制人/小动物/地上物品的哈希；渲染帧数、零步长模拟调用次数。`entities.tsv`：每个复制人和小动物的格子、精确坐标、当前任务、当前动画。`snap_*.bin.gz`：读档后（pre）、每 50 tick、最后一个 tick 的完整格子。
- 运行期间只在探针自己加载的游戏里屏蔽自动存档；不写任何存档。
- 进度在 `state.json`（删掉它即可重新开始一轮）；结果在 `mods/Dev/DivergenceProbe/results/session_*/`。

## 分析
```
dotnet run --project tools/DivergenceAnalyzer -c Release -- "<session 目录>"
```
输出 `analysis/report.md`（每对运行：各字段首次分叉 tick、区块分叉随时间变化、复制人逐个首次分叉的任务/位置、快照逐格差异统计）和热力图 PNG（红=有意义差异，橙=仅比特级差异，绿=复制人）。
分析工具已用伪造数据验证过格式与统计（`scratchpad/tools/fake_session.py`）。

## 已知限制
- 这台电脑没有安装眼冒金星，本次用原版存档；分叉来源（AI、寻路线程、随机数、帧时间）两者共通，以后用眼冒金星存档补测。

## 结果（2026-11-08，session_20261108_191728，c02 第 476 周期，256×384，16 复制人，100 小动物）
报告：`mods/Dev/DivergenceProbe/results/session_20261108_191728/analysis/report.md`；按状态分类的统计：`scratchpad/tools/snapstats.py`。

| | natural | seeded | fixeddt（seeded + 固定帧时间） |
|---|---|---|---|
| 读档后（pre）与第 0 tick 的完整格子 | 完全相同 | 完全相同 | 完全相同 |
| UnityEngine.Random 首次不同 | 读档前就不同（每进程随机种子） | tick 6 | tick 6 |
| 格子首次不同 | tick 1（96 个区块中 86 个） | tick 1（85） | tick 1（85） |
| 复制人精确坐标首次不同 | tick 23 | tick 7 | **tick 214** |
| 复制人格子/任务首次不同 | tick 39 | tick 24 | **tick 214** |
| 60 s 后分叉的复制人 | 11/16 | 11/16 | 10/16 |
| 小动物首次不同 / 60 s 后 | tick 16 / 93 of 100 | tick 16 / 93 | tick 16 / 92 |

fixeddt 两次运行，按格子状态（"有意义差异" = 元素不同、质量差 > 0.1 % 或温差 > 0.01 K）：

| | 10 s 后两次运行之间 | 60 s 后两次运行之间 | 同一次运行自身 10 s 内的变化 |
|---|---|---|---|
| 气体（19.6k 格） | 91 %（其中 1.9k 格连气体种类都不同） | 93 % | 93 % |
| 液体（9.2k 格） | 11 %（元素分布几乎一致） | 16 % | 16 % |
| 固体（59.6k 格） | 2.4 %（温度漂移） | 4.4 % | 3.9 % |

结论：
1. **读档是确定的**，第一个 200 ms 步也确定；**从第二步起整张图同时分叉**，与随机种子、帧时间都无关 → 来源在原生 SimDLL（或托管层无法控制的地方）。**lockstep 不可行**（有数据支撑）。
2. **气体是混沌的**：10 秒后两台机器的气体状态差异和"同一局 10 秒内的自然变化"一样大，等于互不相关。液体形状稳定，只有质量/温度漂移；固体温度漂移很慢。
3. **复制人在固定帧时间下 43 秒内完全一致** → 早期复制人分叉的主要来源是帧时间。之后在周期/日程切换（tick ~213）时大批分叉：表情/睡觉/上厕所等选择不同，受随机数和格子差异驱动。
4. **小动物 3 秒就分叉**（游动/挖掘的选择对环境很敏感）。
5. 随机数在固定种子 + 固定帧时间下 tick 6 仍分叉，大概率是格子分叉的后果（读随机数的逻辑面对的状态已经不同）。
