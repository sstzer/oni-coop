# 联机设计（2026-11-09 重新整理）

本文是总体设计的唯一依据。其他文档是各部分的实现记录和实验数据，与本文冲突时以本文为准。

## 目标（所有设计决定都以此为准）
- **每个人有独立的视角**：自己的镜头、选中、界面、覆盖层。到了眼冒金星阶段，可以各自待在不同的星球上。
- **所有人一起做决定**：任何人都能下指令（挖、建、拆、优先级……）、改建筑设置、管理研究、日程、技能、消耗品，以及选打印舱的人。
- 和自己的朋友玩，所有人都有正版，不赶时间。先做原版，再做眼冒金星（游戏本体相同，眼冒金星在此基础上增加多星球等内容）。

## 整体结构：服务器是唯一的权威，玩家都是同等的
- **服务器**（家里的 Linux 服务器）：跑一份无界面的 ONI（`-coop-role server`），负责模拟整个世界、执行所有人的操作、保管存档。玩家只需要知道服务器的地址。
  - 内部分成两部分：无界面的 ONI，加上接待玩家连接的网络程序（`server/CoopRelay`，历史上叫"中转服务端"）。网络程序负责校验加入、转发、传世界、保存备份。ONI 在服务器本机连接网络程序，所以游戏重启时，网络入口不受影响。
  - 这只是服务器内部怎么分工，对玩家没有区别。两部分作为一个服务部署在 `~/oni-coop/` 里。
- **玩家**：每个人在自己电脑上运行 ONI 和本 mod，加载服务器发来的世界，画自己的画面，用自己的界面。
  - 玩家端不做任何决定：复制人和小动物的行为、格子、物体、数值、研究，全部按服务器的状态显示。
  - 玩家的操作一律发给服务器执行，再同步给所有人。
- **没有"主机玩家"**。代码里"主机"指的就是权威这一方。`-coop-role host`（用某个玩家的游戏当权威）只用于本机开发测试。

## 为什么是这个结构（被实验否定的方案）
| 方案 | 结论 | 依据 |
|---|---|---|
| 一份模拟、给每人串流视频（多摄像机） | 做不到独立视角：游戏的剔除、光照、界面都绑定在唯一的主摄像机上；也做不到在不同星球 | `research-notes.md` |
| 每人各自模拟，只同步指令（lockstep） | 模拟本身不确定，第二个模拟步起全图就开始分叉 | `divergence-experiment.md` |
| 每人各自模拟，定期纠正 | 气体 10 秒内就和权威端互不相关，复制人和小动物几秒就会分叉 | 同上 |
| **一个权威模拟，玩家只显示**（采用） | 各人的镜头和界面天然独立；所有决定只在一处做出 | |

## 玩家端看到什么、怎么跟上服务器（已实现，见 `coop-sync.md`）
| 内容 | 做法 | 实测（本机双开，含无界面服务器） |
|---|---|---|
| 复制人和小动物 | 服务器按帧记录带时间戳的关键帧（位置、动画、朝向、导航类型、瞬时位移）；玩家端关掉它们的 AI 和移动，按服务器的时间线稍微延后回放 | 同一时刻对比，平均误差 0.002–0.03 格；1x/3x、缩到最远、快速平移、频繁切换速度、服务器存档时都不断粮、不跳变（`coop-sync.md` 3a+） |
| 格子 | 按每个玩家的视野发送有变化的格子，玩家端写入，并定期把屏幕内的格子拉回服务器的值 | 约 18 kbps |
| 物体（建筑、物品、蛋、标记、复制人……） | 生成和销毁时发游戏自己的存档数据（ID 不变），物品另发所在容器、位置、质量、温度，每 5 秒对账一次；玩家端关掉会自己造出或消耗物体的建筑逻辑 | 约 16 600 个，对比一致 |
| 装备、分配、建筑动画和指示条、视野内的管道、运输轨道上的物品 | 按服务器回放，玩家端本地逻辑改不动；建筑动画在开始的那一刻记录，和复制人放在同一条时间线上播放（门和走过的复制人对得上） | 对比一致 |
| 干活的反馈：进度条、飘字 | 服务器记录游戏生成的每一个，放进时间线；玩家端本地生成的挡掉 | `coop-sync.md` 3p |
| 时间线 | 复制人、建筑动画，以及物体和物品、格子、管道、状态图标、建筑是否在工作，都按服务器时间延后同样的缓冲显示（含全局数值条）；玩家的指令和面板设置立即显示 | `coop-sync.md` 3o |
| 复制人外观：手里的工具、光束和击中特效、衣帽头盔、表情、想法和聊天气泡 | 服务器把变化挂在动作关键帧上发出，玩家端在时间线的同一时刻应用；每 2 秒核对一次校验值，对不上就要一份完整的（眨眼、说话嘴型由玩家端自己算） | 117 个复制人和小动物，对比一致 |
| 建筑是否在工作（通电、启用、自动化允许……）、电池电量、电路用电、自动化信号 | 服务器发变化，玩家端照着设置并挡住本地代码；玩家端不再自己跑电路模拟。灯光照明范围、电路面板数值都由此一致 | 见 `coop-sync.md` 3m |
| 状态图标、效果、通知 | 服务器发每个物体的状态条目（只发变化）和效果表；玩家端照着显示，本地代码只能和服务器一致；玩家端认不出数据的条目用服务器给的各个占位符的值，按玩家自己语言的模板显示 | 约 12 000 个物体、540 个效果，对比一致；约 3 KB/s |
| 周期报告 | 服务器把游戏的报告调用按项累加，每 2 秒发一次；玩家加入时发一次今天的整份 | 44 项，对比一致 |
| 复制人进出火箭仓 | 游戏把编号转给新物体时，服务器发"替换" | 存入、放出后两边一致，无报错 |
| 数值、死亡、研究、经验和技能点、时钟、打印舱 | 玩家端不再自己计算，只显示服务器的值 | 对比一致 |
| 兜底 | 断线重连后、服务器重启后自动重新获取世界；也可以手动"重新同步" | 重连后约 20–30 s 恢复 |

## 大家一起做决定（已实现）
- 工具：挖、建、管线、取消、拆、优先级、拖把、清扫、消毒、收获、攻击、捕捉。在执行的地方拦截，发给服务器执行，再由所有人用游戏原本的代码重放。重放时新建的物体沿用服务器分配的 ID。
- 设置面板、物体按钮、管理界面：登记了 127 个游戏方法，按"对象 + 方法 + 参数"同步。只有玩家在界面上的操作才算，游戏自己调用这些方法不拦截。直接改字段的面板（定时传感器、时间段传感器）按"面板改了目标的哪些字段"同步。
- 由复制人完成的结果（启用或停用、门、手动开关）：服务器上状态真正改变时广播。
- 打印舱：服务器生成每一轮的候选人，大家看到同一批，任何人都可以选，也可以全部拒绝。
- 暂停和速度：任何玩家都可以请求，由服务器执行。没有玩家在游戏里时服务器自动暂停。
- 玩家的操作要等服务器执行后才显示（约一个来回的延迟）。这是你确认过的，不做本地预览。

## 网络
- 现在全部走 TCP（玩家 → 服务器的网络程序 → 服务器上的 ONI）。按视野同步，每个玩家的流量约 6 KB/s 加格子同步。
- 真实线路实测（这台电脑到服务器往返约 247 ms，无丢包）：各项同步都正常，抖动 p98 约 160–190 ms，玩家端自动把缓冲加到约 0.4 s。
- 当初设计的"不可靠 UDP + 按确认状态做增量"（`sync-bandwidth-experiment.md`）暂不做。它只在丢包多的线路上明显更好，现在的实测线路没有丢包，而且 SSH 隧道和内网穿透很可能只能走 TCP。以后真遇到丢包卡顿再做。
- 访问方式：开发时用 SSH 隧道；正式使用内网穿透或开放公网端口（`coop-skeleton.md` 部署一节）。

## 部署（服务器 `ssh s`，`~/oni-coop/`）
- 网络程序已经作为 systemd 用户服务运行，开机自动启动。服务器存档的备份在 `relay-data/rooms/<房间>/backups/`（每个周期的自动存档，保留 20 份）。
- 无界面 ONI **还没在服务器上跑**：它是 Steam 版，必须由一个拥有游戏的 Steam 账号登录。同一账号同一时间只能在一台电脑上运行游戏，所以服务器要有自己的账号（不绕过 Steam 校验）。到位后：在 Linux 上装好 Steam 和游戏，让 Steam 在无界面下保持登录，ONI 和网络程序作为一个服务一起启动、一起看护。
- 服务器上的游戏语言设成和玩家一样（简体中文，`kplayerprefs` 里 `SelectedLanguageType=Preinstalled`、`SelectedLanguageCode=zh_klei`）。玩家端已经能用自己的语言显示服务器给出的文字（`coop-sync.md` 3n），但数字的单位（"千克"还是 "kg"）是服务器写的。
- Windows 上已验证过无界面运行（`-batchmode -nographics`）：读档 9 s，模拟正常，60 fps 上限下约 40–54 fps，内存约 3.5 GB。mod 已处理无界面下的报错窗口、需要点"好的"的对话框和帧率。

## 还没做（按目标排序）
1. **服务器真正跑起来**：Steam 账号（需要你决定）→ 在 Linux 上实测无界面运行 → 和网络程序合成一个服务。
2. **3 人以上**还没测。
3. **眼冒金星**：多星球（每人可以待在不同星球）、火箭和星图、跨星球转移、辐射。现在的消息都带星球编号，格子按全局编号同步，为这一步预留了。
4. 服务器整个停住时（存档 0.85–2.3 秒、有人加入时 2–7 秒，本机数据）所有人一起等，玩家端会显示"服务器正在存档…"。垃圾回收已安排在存档这段时间里（`coop-sync.md` 性能一节）。可以把服务器的自动存档调成几个周期一次。
5. 流星雨还没同步：玩家端自己模拟流星和导弹，碎块会闪现（`coop-sync.md` 还没做）。
6. 小的遗留：服务器给出的文字里，数字的单位写法和少数认不出的词仍是服务器的语言（朋友和服务器语言不同时才会看到）。

（原来的第 2、3 项"大家看到的一致""大家都能做的决定"已完成，见 `coop-sync.md` 3h–3k 和"设置面板"一节。多滑条面板在原版里只有开发用建筑用到，不用做。）

## 本机测试
- `tools/coop-local-test.sh --server-mode`：无界面服务器加一个带画面的玩家端，玩家走模拟的约 300 ms 线路。
- `--both-args "-coop-autotest cmds"`：自动下指令、改设置、选打印舱的人，并在同一时刻导出两边的状态；`tools/coop-compare-shots.py` 逐项对比。
- `--both-args "-coop-autotest motion -coop-profile 10"`：运动测试，服务器按阶段切换速度、存档，玩家端缩放和平移镜头，两边报告卡顿、断粮、跳变。
- `--remote s --sim off`：走服务器上的网络程序和真实线路。
- 同机双开的方法：`tools/MultiLaunch` 关掉 Unity 的单实例锁；两份游戏同账号登录，Steam 允许。

## 已放弃或过时的设计（只作记录）
- 视频串流、多摄像机（`research-notes.md`、`src/MultiViewExperiment`）：已放弃。
- 玩家当主机、主机交接、"过渡期由朋友的游戏当权威"：已放弃，只有服务器是权威。
- 玩家的操作先在本地预览：不做。
- 复制人回放"寻路路径 + 导航过渡事件"，让玩家端用游戏的 Navigator 自己走：没有采用。现在用带时间戳的关键帧，实测足够准确。
- 不可靠 UDP 加按确认状态的增量、视野分区块多路传输：暂不做（见"网络"一节）。
